# 阅读学习闭环规格

本文件描述本地 OpenVoca 最核心的学习路径：用户先生成阅读内容，再在上下文中识别不熟悉的词，最后提交反馈并进入下一轮。

## 编排与阅读状态

- **AC-LOOP-001-01**：应用进入首页时先显示编排器；用户触发生成后，页面切换到阅读状态。
- **AC-LOOP-001-02**：生成结果必须按 token 渲染；目标词需要有可识别的视觉标记，普通可点击词不能被误标为目标词。
- **AC-LOOP-001-03**：用户离开阅读页再返回时，当前阅读句子和可继续复习状态不能丢失。

## 目标词与生成节奏

- **AC-LOOP-002-01**：目标词推荐必须来自当前本地词库中已到期、未毕业的词。
- **AC-LOOP-002-02**：刷新目标词推荐不能消耗 cooldown；只有进入下一轮生成时才推进 cooldown。

## 反馈与进度确认

- **AC-LOOP-003-01**：用户点击继续/复习时，应用先展示本轮词汇变化预览，而不是直接提交。
- **AC-LOOP-003-02**：正式提交反馈时，已认识、未认识、原始目标词与当前句子必须一起送达后端。
- **AC-LOOP-003-03**：用户修正词元后，修正结果必须同时影响进度预览和最终提交。

## 猜谜模式

- **AC-LOOP-004-01**：猜谜模式返回 clue、question 和 answer；进入复习前应先隐藏答案，只展示谜面与线索。
- **AC-LOOP-004-02**：猜谜 prompt 必须强制英文输出，并保留用户选择的场景和自定义细节。
- **AC-LOOP-004-03**：当模型返回无效猜谜 JSON 时，后端必须明确失败，前端必须把错误展示在编排器中。

## 流式生成

- **AC-LOOP-005-01**：SSE 生成过程中，前端应展示词数进度；收到 complete 事件后切换到阅读结果。
- **AC-LOOP-005-02**：生成失败时，前端应显示具体错误，后端应返回可区分的失败状态。

## 查词、朗读与词元修正入口

- **AC-LOOP-006-01**：用户在阅读中点击可学习词时，应能查看定义并标记认识/不认识。
- **AC-LOOP-006-02**：阅读句子和单词定义都应支持朗读；优先使用后端 TTS 音频，失败时可回退浏览器语音。
- **AC-LOOP-006-03**：定义浮层应允许修正当前词元，并避免在词元与查询词相同时显示重复标签。
