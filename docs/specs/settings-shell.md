# 设置、应用壳与统计规格

本文件描述本地应用的非学习核心能力：设置持久化、配置导入导出、应用壳状态、更新提示、静态入口和统计页管理交互。

## 设置存储与 API

- **AC-SET-001-01**：设置按 namespace/key 存储；单项写入后可读取，缺失项返回空语义。
- **AC-SET-001-02**：同一 namespace 下可批量写入和读取；读取全部设置时必须按 namespace 分组。
- **AC-SET-001-03**：删除 namespace 或清空全部设置时，应返回删除数量；删除空目标应安全返回 0。
- **AC-SET-001-04**：设置 API 应支持读取全部、写入单项、批量写入、读取 namespace、清空全部，并拒绝空字符串值。

## 设置导入导出与语言

- **AC-SET-002-01**：前端导出设置时必须排除 provider API key；如果某 namespace 只剩敏感字段，则整个 namespace 不导出。
- **AC-SET-002-02**：前端导入设置时应合并合法字符串值，跳过 API key、非字符串值和非对象 namespace。
- **AC-SET-002-03**：用户切换界面语言后应持久化 locale，并更新当前缓存的阅读界面文案。

## 阅读显示设置

- **AC-SET-003-01**：阅读内联设置可以修改主题等显示偏好，并同步到本地缓存。
- **AC-SET-003-02**：点击阅读设置空白遮罩应关闭设置面板，不改变阅读内容。

## 敏感字段保护

`GET /api/settings` 是通用设置读取接口，会原样回传整个 `provider` namespace，包含明文密钥。
前端在写入本地缓存与导出时会主动跳过该字段，因此界面不会暴露它，但接口本身是敞开的。

- **AC-SET-004-01**：设置读取接口不得包含 provider API key 键，既不得回传明文，也不得回传掩码值。

密钥的展示片段只由 provider 读取接口提供（见下节），不由通用设置接口提供，
这样本地缓存与导出内容天然不含任何密钥痕迹。

## 密钥存储与交互

provider 的密钥与端点、模型相互独立：更换端点或模型不应影响已保存的密钥。
这既是使用上的期望，也是消除一类缺陷的关键——原实现把密钥与端点、模型放进同一个写入请求，
"空密钥"在不同代码路径上同时表示"不修改"与"设为空"，导致运行时配置与持久化配置分歧：
写入端点为空的请求会抹掉内存中的密钥，而数据库仍保留它，直到重启后密钥又"恢复"。

密钥的写入与清除是两个独立操作，不由写入空值触发。空字符串不再承担任何语义，
这与既有设置接口拒绝空值的行为一致。读取时以布尔状态与不可逆提示片段表达，不提供可用于调用的内容。

- **AC-SET-005-01**：修改 provider 端点或模型不得改变已保存的密钥；密钥只能由显式的保存或清除操作变更。
- **AC-SET-005-02**：运行时生效的 provider 配置必须与持久化配置一致，重启前后对外表现一致。
- **AC-SET-005-03**：provider 读取接口以"是否已配置"布尔值与不可逆提示片段表达密钥状态，不得回传可用于调用模型的密钥内容。
- **AC-SET-005-04**：写入空密钥必须被拒绝；清除密钥必须是独立操作，不由写入空值触发。
- **AC-SET-005-05**：清除密钥后，运行时与持久化都不再持有该密钥。
- **AC-SET-005-06**：通用设置写入接口不得修改 provider 配置，provider 配置只经由 provider 接口写入。
- **AC-SET-005-07**：密钥在已配置状态下只以只读形式展示，界面不得把该展示内容放入可编辑输入；编辑必须从空输入开始。

`AC-SET-005-06` 的理由不是对称性，而是运行时一致性：provider 配置存在内存中的活跃副本
（LLM 客户端），通用设置写入接口只改数据库、不重建该副本，会重新制造运行时与持久化的分歧。

### 自定义请求头

自定义请求头与密钥的处理方式不同，差异来自可编辑性：密钥是只写的，客户端从不持有它，
因此只能以状态加提示表达；请求头需要被查看和逐项修改，客户端必须拿到完整内容才能编辑。

由此请求头随 provider 配置整体替换，空集合明确表示不使用自定义头——空值在这里只有一种含义，
不构成歧义。请求头可能承载会话凭据，因此与密钥同等对待，不出现在通用设置读取与导出中。

- **AC-SET-005-08**：provider 读取接口回传自定义请求头内容，以便逐项编辑。
- **AC-SET-005-09**：自定义请求头必须从通用设置读取与导出中排除，与密钥同等对待。
- **AC-SET-005-10**：更新 provider 配置时请求头与端点、模型一并整体替换，空集合表示不使用自定义头。

## 应用壳与静态入口

- **AC-SHELL-001-01**：健康检查 API 应返回后端可用状态。
- **AC-SHELL-001-02**：生产静态路由应把未知前端路径回退到 `index.html`。
- **AC-SHELL-002-01**：当后端报告有新版本时，应用应延迟显示更新提示；无更新时不显示提示。
- **AC-SHELL-002-02**：用户关闭更新提示后，当前会话不应继续展示该提示。

## 统计页交互

- **AC-STATS-001-01**：统计页的危险删除操作应与行内编辑入口分离，避免误删。
